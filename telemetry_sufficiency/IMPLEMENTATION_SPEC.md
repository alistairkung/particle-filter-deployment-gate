# AIMS5701 · Implementation and verification contract

**Status — awaiting approval.** The [scientific protocol](SCIENTIFIC_SPEC.md) governs populations, fitting, uncertainty and verdicts. This contract defines the interfaces and tests needed to implement it. The proposed commands below are acceptance criteria for subsequent implementation.

## Structure and reuse

Keep study code, configuration, documentation and outputs under `telemetry_sufficiency/`. Reuse the frozen pilot at `bb20ebe` by import. Keep its inputs, code, test suite, plots and retained evidence byte-identical. Its CLI and import layout remain usable from the documented pilot working directory. Use the existing Python, NumPy, SciPy, SimPy, pytest and Matplotlib stack. Provide one study entry point from the repo root that makes the pilot's existing top-level `experiments` and `simulator` imports resolvable. Avoid a second FIFO implementation.

| Responsibility | Reuse | New study responsibility |
|---|---|---|
| Plant and exogenous inputs | [SerialDB and Model](../feasibility_pilot/simulator/model.py), [named RNGs and input tapes](../feasibility_pilot/simulator/inputs.py) | Root scheduling, condition onset, stable raw-input evidence and passive lifecycle events. |
| Evaluation | [Deadline windows, DB work, horizon freeze](../feasibility_pilot/experiments/observations.py), [pilot replay fixture](../feasibility_pilot/experiments/validation.py) | Truth and paired-outcome extraction in an evaluator-only path. |
| Estimation | Locked scientific fitting rules | Pure feature extraction from a typed observation history. Fitting takes a feature matrix and the relevant development response. Prediction takes learned parameters and permitted features only. |
| Evidence | Pilot CLI, completeness, audit and reproduction patterns | Separate study manifests, data partitions, classifier/regression fits, score reconstruction and five-question report. |

## Workstream 1 — Time-causal outbox telemetry

**Production analogue.** A passive lifecycle collector timestamps committed inserts and completed publication marks against the simulated event clock. Commit is the creation/visibility instant in this model. A persistent row identity links insert to mark inside the collector. No row identifiers leave it. An ordinary pending-row poll could recover count and oldest age but could overlook rows both inserted and marked between polls. The feed supplies the mark evidence needed for throughput and completed delay without changing DB demand.

**Producer.** Adapt the existing commit and mark completion callbacks in a study-local wrapper. Emit only the row identity, event type and event timestamp to the collector after the physical effect at that tick. A claim, acknowledgement, write admission or reserved service completion cannot emit a mark. Ineligible writes cannot emit an insert. Keep the separation explicit: collector inputs are these two event types and a clock tick. The public predictor receives neither the collector nor a plant reference. Do not hand it the pilot's mixed horizon records, write objects, visit ledger or flattened tables.

**Clock and ordering.** Use signed integer nanoseconds relative to the cut. Start at −60 s with empty collector state. Produce twelve five-second aggregates ending −55 s through 0 inclusive. There is no artificial initial reading. After processing every scheduled event at an interval end t with the pilot's stable admission/callback ordering, sample pending rows and seal the count of marks and completed delays for (t−5 s,t]. A mark at the left boundary belongs to the prior interval. A mark at the right boundary contributes once and its row is absent from the ending snapshot. A row committed at t is pending with age zero if its mark remains outstanding. The last on-time reading at t=0 is available before selecting the action for arrivals strictly after zero.

| Public field | Type and meaning |
|---|---|
| `interval_start_ns`, `interval_end_ns` | Integer relative measurement times, five seconds apart. |
| `available_at_ns` | Integer delivery time, at or after the interval end. Expose only after actual delivery. |
| `pending_count` | Nonnegative integer of committed eligible rows that have yet to complete a mark. Includes claimed and acknowledged rows awaiting a mark. |
| `oldest_pending_age_s` | Nonnegative seconds since the oldest such commit, zero if empty. Count distinguishes empty from a newly committed row of age zero. |
| `publication_throughput_per_s` | Completed marks in the interval divided by five. Zero is measured. |
| `completed_delay_median_s` | Median of mark time minus matched commit time for rows marked in the interval, in seconds, including commits before the interval. Average the middle two values for even counts. Null iff no mark completed. |

**History API.** Given a decision-time cutoff u, return immutable value records satisfying end ≤ available_at ≤ u in interval-end order. The five-second schedule is known to every caller. A scheduled interval with no delivery yet is absent. The controller sees the same absence for a lost sample and a sample still in transit. The evaluator privately records the distinction. Delay/missing fixtures defer or suppress aggregate delivery only. A late aggregate never rewrites an earlier returned history. If several deliveries coincide, include them all before returning the as-of history. The primary study has one successful delivery per interval at its end. Reject duplicate intervals, retroactive delivery, unknown fields and nonfinite numeric values.

**Feature boundary.** Predict from as-of history and the fixed public clock. Current uses the delivered record with greatest interval end, including an explicitly undefined delay if that record has no marks. If none has arrived, current measurements are undefined. For temporal summaries intersect available records with the six scheduled ends in the final 30 s. Means need one defined value, slopes need two distinct measured ends. Count deliveries separately from defined metric counts. No marks is measured zero throughput even where the delay is undefined. Expose only numeric features named in the scientific ladder, current-value undefined flags, summary undefined flags and the history-level delivery count. Do not expose raw routes, actual share realisations, attempted writes, source IDs, rates, exact ACK duration, queue state, root keys, branch names or administrative metadata. A data custodian maps opaque record keys to feature rows outside the estimator; strip keys before fit and prediction.

**Acceptance fixtures.**

1. Hand-schedule a commit just before a boundary, a commit at it, and marks on either side and exactly at it. Check pending, oldest age, mark count/rate and median of an even and an odd set. Check a row acknowledged but still awaiting its mark, a never-committed outstanding write, an empty interval, a fresh zero-age pending row and an interval with pending rows and zero marks. Check exact ties at zero and the first/last bin.
2. Interrupt one delivery, delay another past the cut, and return a third out of order. Compare as-of results immediately before and at delivery. Test undefined means/slopes and defined counts with zero, one and two usable samples. Verify repeated reads of an earlier as-of time are identical. Assert field allowlist recursively on serialised public values and on the numeric design matrix.
3. Capture the live prefix, stop and serialize it. Replay with different actions, future tapes, future query shock and a changed drain. Independently reconstruct the prefix by time-filtering completed lifecycle evidence; compare canonical public bytes, including nulls and delivery times. Include both an outstanding write and an unmarked row at the cut. Make both complete later. Mutating any private sibling outcome, scenario metadata, or evaluator-only prediction must have no effect on features or public predictions for the same action.
4. Record a deterministic trace with and without the passive collector. Verify equality of FIFO visits, event lifecycles, physical state and endpoint. Run the public predictor on isolated observation data with no private store accessible.

## Workstream 2 — Matched counterfactuals

**Generation.** Reuse the pilot master seed with a fresh versioned study namespace, `outbox-sufficiency-v1`, disjoint from pilot, development fixtures, fold ordering and bootstrap. Freeze the exact namespace and key grammar in config. Derive PCG64 substreams through the pilot SHA-256 naming rule. Bind the study root key to condition, partition and within-cell index 0–399, never to the action. Use independent prefix/future and application-arrival, routing-uniform, business-work, reference-query and extra-query streams. Use UTF-8 slash-separated key components as in the pilot and forbid delimiter collisions. No random stream may depend on branch execution order, worker identity, model fit or future outcomes.

Use one common 60 s prefix input tape per root at 25%. Reference arrivals and service continue uninterrupted. For established contention, take an independent rate-2 prefix extra-query stream restricted to (−30,0] (discard extra events outside that interval including their assigned work). Preserve distinct stream IDs, time ordering and pilot work rounding. Add a deterministic slowdown fixture that compares its reference-query arrivals and work to a nominal-publisher tape generated from the same primitive draws at 3.5/s, including at least one query in each prefix segment. The legacy C5 generator suppresses reference queries and cannot generate the study’s slowdown condition. For the slow publisher, finish all events at −30 s under nominal acknowledgement then start the 50 ms rule for newly begun waits. The pilot's C5 `slow` flag switches only after zero. Use the existing nominal acknowledgement path with a study-local replacement of the immutable timing config at the onset; an already scheduled acknowledgement retains its due tick. Do not change the frozen pilot. Holds/promotions share the same post-cut publisher rule.

Replay the prefix to obtain a fresh live plant for each continuation. Assert the same physical cut digest including routes and the same public history. Also compare cut-time condition parameters, eligibility, ordered outstanding inputs and pending acknowledgement due time, which the pilot digest alone does not fully encode. The pilot input helper exposes route-adjusted work. Materialise or regenerate the named primitive streams before those draws are transformed. Record canonical application tuples (tick, request ID, uniform U, unit-exponential business draw E), and query tuples (tick, source, query ID, service demand). At each tick use pilot priority for external events and stable application, reference, extra order. Bind the raw tapes to observed admissions by comparing every request and query, including pilot-rounded business work plus atomic insert time. Digesting two planned tapes alone cannot verify the inputs actually applied. Preserve each request's identity, arrival, uniform and unit business draw; Java selection is uniform < share and only switched requests change realised work. Match query identity, arrival and demand. Query demand is independent of routing. Retain raw-input digests and verify the paired mapping before scoring. For the surprise pairs, introduce only the independent extra-query stream after zero. Do not carry a shock flag into prediction. Identical histories must yield identical predictions for each given action across ordinary and surprise futures.

**Acceptance fixtures.** Compare interrupted-prefix replay followed by the same action with an uninterrupted simulation event for event and window for window. Cover all publisher phases at the cut, an active DB visit spanning the cut, queued work, previously routed writes, and an acknowledgement spanning −30 s. Verify onset just before/at/after −30 s and exactly at zero. Probe route uniforms below 0.25, at 0.25, between shares, at 0.60 and above. Compare raw draw identities as well as route-adjusted demands. In an equal-work fixture the two actions must have identical route-blind physical trajectories and outcomes. Reverse branch order and change worker count; canonical records must match. Preserve pilot deadline, drain, strict >5% and empty-window boundary tests. Include a synthetic paired-outcome table with all four cells and verify the sign and denominator of D.

## Workstream 3 — Study execution and independent reconstruction

**Data custody and fitting.** Enumerate a versioned root inventory by condition and partition before collecting outcomes. The custody layer joins authorised development targets to feature rows. Build the evaluator-only reference in a separate feature pipeline. Persist the per-root target and all out-of-fold predictions with fold and training-inventory hashes so a reviewer can reconstruct both selections. The outbox fitting path cannot read its model, predictions or truth columns as covariates. Root keys, condition strata and fold assignments may organise rows only outside the estimator. Freeze a five-fold out-of-fold selection ledger and final fits for every level, target and action. Use float64, fixed feature ordering and deterministic full-batch fits. For logistic models use SciPy L-BFGS-B, zero initial parameters, stable log-sum-exp losses, analytic gradients, ftol 1e−12, gtol 1e−8 and a 2,000-iteration cap. Ridge linear fits use a deterministic linear solve with an unpenalised intercept. Fix and record library versions and solver settings in the development manifest. For multiclass use sum-to-zero logits or an equivalent identifiable full symmetric parameterisation with centred intercepts and the protocol penalty. Record all coefficients, preprocessing constants, class order, clipping, convergence status and feature order. A fitting failure cannot silently drop a model or root.

**Protected evaluation.** The lock records development evidence hashes, selected candidates, transforms/fits, seed inventory, protocol/config versions, score comparisons and implementation source digests. Generate protected roots only after validating the lock. Build permitted predictions before the scoring join; use separately authorised physical covariates for the evaluator-only diagnostic. Keep predictions immutable and linked by opaque external keys. Reject a changed lock, duplicate/missing roots, orphan branches, cross-partition descendants or a partial stage. Restrict the fit command to a development-only input schema. Test that supplying protected data fails before any fit. This is protection against analytical reuse with auditable stages in a shared workspace; document any human access on the run manifest. Mark the protected partition consumed once outcomes have been inspected.

**Evidence retained per run.** Use separate files or tables with explicit schemas, units and primary keys. Operational keys are private except in a transport envelope removed before feature extraction.

| Evidence | Minimum contents |
|---|---|
| Manifest and inventory | Config and protocol hashes, study and pilot revisions, uncommitted source hashes, dependency versions, seed names, clock/tie ordering, expected roots/branches by stage, validation status, lock digest and protected access/consumption record. |
| Permitted history | One immutable array per root of the public fields, and its canonical content hash. No hidden columns in the serialised history. |
| Private evaluator evidence | Condition, realised query work sum and observation duration, queued-service sum and active residual at the cut, physical and exogenous input hashes, paired action/window eligible counts and misses, frozen branch endpoints, private per-root coupling checks. |
| Fitting and predictions | Fold map, development out-of-fold scores and claim selections, transforms, features and coefficients, model and input hashes, per-root predictions for each target/model/action, separate evaluator-only fits and predictions. |
| Scientific outputs | Four paired cells and denominators, all losses, stratum results, score differences, bounds, calibration bins and confusion counts; locked verdict and machine-readable pass/failure reasons. Retain plots of physical measurements by condition, both action risks/calibration and paired score gains with uncertainty. |

Independent reconstruction compares counts and timestamps exactly. Compare continuous model predictions, scores and bounds with absolute and relative tolerance 1e−10; compare claim decisions and verdicts exactly, even if two numerically close results straddle zero. Public-history equality across forks uses canonical bytes, including timestamp order and nulls. Use atomic writes and root-level completion markers. Retry identical stages by input and code digest. Preserve failed attempts and their manifests, invalidate downstream claims on failure, and forbid writes into frozen pilot paths. Retain deterministic fixtures and raw lifecycle/visit traces for preselected example roots and validation failures. The full run can regenerate tapes from its manifest. Independent verification must not rely solely on a stored boolean, digest or reported verdict.

**Command contract.** From the repository root, after installing the pinned environment described in the pilot README, provide these entry points (the interpreter below is that environment's Python). A successful run records its own exact commands and paths.

```sh
feasibility_pilot/.venv/bin/python -m pytest -q telemetry_sufficiency/tests
feasibility_pilot/.venv/bin/python -m telemetry_sufficiency validate --run telemetry_sufficiency/results/v1
feasibility_pilot/.venv/bin/python -m telemetry_sufficiency develop --run telemetry_sufficiency/results/v1
feasibility_pilot/.venv/bin/python -m telemetry_sufficiency lock --run telemetry_sufficiency/results/v1
feasibility_pilot/.venv/bin/python -m telemetry_sufficiency evaluate --run telemetry_sufficiency/results/v1
feasibility_pilot/.venv/bin/python -m telemetry_sufficiency audit --run telemetry_sufficiency/results/v1
```

Run the [pilot tests and clean reproduction](../feasibility_pilot/README.md#reproduce-the-experiment) from its own working directory with a fresh output directory. For the comparison call the existing read-only `experiments.compare.compare(original, reproduced)` function and save its return value under the new study run. The pilot comparator CLI writes a receipt into its first argument, so invoking it on the frozen directory would modify an original artifact. Validate the original config, computational signature, original scientific file digests and GO verdict against `results/frozen`. Also verify no tracked pilot artifact changed from `bb20ebe`. Attach the reproduction receipt to the study's audit. Provide one documented report command that requires this receipt and the completed independent audit.

**Independent acceptance.** Assign an independent reviewer to inspect producer/estimator separation and adversarial leak fixtures. Have another verification path reconstruct both claims, paired cells, scores and verdict from retained history, truth, window counts, predictions, fit locks and root partitions. Recompute features and apply stored coefficients to check predictions, decode all windows independently to check Y and D, rederive fold selection from retained development evidence, verify the prior, calculate stratum gains, SEs, simultaneous bounds and descriptive intervals. Verify the stronger constant comparator and an example where both action forecasts improve while signed prediction does not. Check that a result confined to the publisher label, a single passing claim, nominal diagnostic significance or a better evaluator-only score cannot by itself produce READY. The audit must replay every protected root and every ordinary or surprise branch from the frozen manifest. Regenerate named draws and verify actual admissions. Using a separate extractor over write timestamps, completed lifecycle events, scheduled deliveries and visit/enqueue times, rederive the complete public history, cut query work in (−30,0], unfinished work, and every window denominator and miss count under the original cutoff. Do this before using saved outcomes and predictions to reconstruct statistics. Reconstruct without calling the production feature/window/truth extraction helpers being checked. Compare independently derived values with retained records and opaque-key mappings. Raw evidence may be streamed during audit; retaining all event traces is optional when reproducible replay covers the entire protected inventory. Mutation tests must fail after swapping two root joins, corrupting a single stored query work sum or window tally, exposing a hidden field, or changing one prediction. Record replay counts, hashes, discrepancies and outcome of the independent review. No published READY verdict before reconciliation.

**Delivery.** Implementation produces the reproducible command guide, machine-readable evidence, concise tables/plots and an Experimental Readiness Report with one verdict under the [scientific stopping rule](SCIENTIFIC_SPEC.md#stopping-interpretation-and-report). A valid negative or inconclusive outcome completes the study. No production monitoring, deployment decision policy or particle filter is required.
