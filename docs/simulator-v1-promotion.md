# Simulator v1 promotion and freeze plan

The physical baseline is the frozen [feasibility implementation at bb20ebed72471f43443c873a11b2ac6e32fbbc00](https://github.com/alistairkung/particle-filter-deployment-gate/tree/bb20ebed72471f43443c873a11b2ac6e32fbbc00/feasibility_pilot). The study implementation that generated the telemetry lock was fbb64198686b75e5ffcd7dcabf4935527fa7a659. Its [completed evidence snapshot at 624541bae2405fe47a59a193a55482775a7e0d0a](https://github.com/alistairkung/particle-filter-deployment-gate/tree/624541bae2405fe47a59a193a55482775a7e0d0a/telemetry_sufficiency) includes the authoritative report. The [pilot specification](../feasibility_pilot/SPEC.md), [scientific protocol](../telemetry_sufficiency/SCIENTIFIC_SPEC.md) and [implementation contract](../telemetry_sufficiency/IMPLEMENTATION_SPEC.md) define the scientific semantics.

| Future boundary | What belongs there | Regression evidence |
|---|---|---|
| Physical plant | Extract shared non-preemptive FIFO scheduling, Ruby/Java synchronous service, atomic commit and outbox insertion, claim, off-DB acknowledgement and completed mark from the pilot’s simulator/model.py. Preserve integer nanoseconds, tie ordering and inherited service. | Pilot C0 analytical queues, C1 route-blind placebo, DB/outbox conservation, residual service and in-flight acknowledgement fixtures. |
| Workload and paired replay | Reuse named deterministic input streams, stable request identities, background queries, route uniforms and underlying service draws from simulator/inputs.py and telemetry_sufficiency/plant.py. Preserve matched hold/promote inputs and identical cut state. | Same-policy replay against uninterrupted execution, draw-to-admission audit, cutoff/onset ties, C2–C5 outcomes, protected replay ledger. |
| Observation boundary | Expose immutable available-as-of histories from telemetry_sufficiency/observation.py. Retain five-second measurement windows, availability clock, pending count and age, mark throughput, completed delay, and distinct missing/empty/no-mark behaviour. | Exact public profiles across incompatible futures, delayed/missing delivery fixtures, unchanged physical trace with passive collection. |
| Study and evaluator | Leave experimental condition assignment, breach scoring, hidden state, paired outcomes, storage, priors, diagnostic regressions, model locks, reports and bootstrap in their respective studies. A forecaster receives only permitted histories and candidate actions. | Existing deadline/cohort, held-out split, feature allowlist, scoring, reconstruction and publication tests. |

Promote the shared machinery in a separate PR after the milestone and storage PRs merge. Keep the existing study entry points working while moving imports. Compare the resulting plant against both original evidence snapshots with the same seeds, including action-specific predictions and numerical receipts. Review the complete scientific and engineering diff before approving a stable tag such as `simulator-v1.0.0`. There is no approved release tag at this milestone. A subsequent change to physical or observation semantics requires a documented scientific revision with regression evidence.

**Protected-data restriction.** The historical telemetry evaluation has been inspected. Reserve fresh independent protected roots for the particle-filter milestone, keep root families intact, and use development data for observation likelihoods, thresholds, tuning and selection.
